# Аудит репозитория MYDON

Раз в неделю пройти по репозиторию и вынести владельцу то, что накопилось и
требует решения: забытые ветки и worktrees, спеки без записанного решения,
планы без леджера, миграции мимо журнала, сломанные паспорта агентов,
протухшие вопросы.

## Когда запускать

- Еженедельно, по расписанию (см. «Расписание» ниже) — основной режим.
- Перед мержем крупной волны: спека без решения и план без леджера видны до
  того, как ветку закрыли и контекст потеряли.
- После разбора аварии: остаётся worktree, который никто не снесёт сам.
- Когда «git cherry врёт» и `git log` перестал совпадать с содержимым файлов —
  аудит показывает, сколько хвостов накопилось на самом деле.

## Команда

```bash
node tools/repo-audit.mjs            # печатает секцию и дописывает её в memory/open-questions.md
node tools/repo-audit.mjs --dry-run  # только печатает, ничего не пишет
```

Скрипт читает репозиторий (git — только `for-each-ref`/`list`/`status`) и
пишет ровно один файл — `memory/open-questions.md`. Секция за сегодняшнюю дату
одна: повторный запуск в тот же день ЗАМЕНЯЕТ прошлую, а не копит ленту.
Проверка паспортов идёт через `pnpm --filter @mydon/agents check:passports` —
это единственный внешний вызов, который может быть небыстрым.

## Что делать с находками

| Находка | Решение |
|---|---|
| Ветка старше 30 дней | сверить СОДЕРЖИМЫМ файлов (после squash `git cherry` врёт), затем снести `git push origin --delete <ветка>` — или объяснить, почему живёт |
| Worktree | разбор закончен → `git worktree remove <путь>`; нужен дальше → записать зачем |
| Неотслеживаемые файлы | либо в git, либо в `.gitignore`; каталоги вроде `.agents/skills/*` принадлежат другому инструменту и остаются неотслеживаемыми намеренно |
| Спека без решения | дописать `docs/decisions/<дата>-<slug>.md` с ПРИЧИНОЙ — решение без причины пересматривается вслепую |
| План без леджера | закрыть план или отметить в `.superpowers/sdd/<план>/progress.md` строкой `complete`; если план брошен — сказать это вслух |
| Миграция вне журнала | дописать тег в `packages/db/drizzle/meta/_journal.json`: на проде миграции без тега не существует |
| Паспорта: ПРОБЛЕМЫ | чинить сразу — расписание зовёт навык, которого нет, значит рутина молча не работает |
| Вопрос старше 60 дней | закрыть решением (в `memory/decisions.md`) или снять как неактуальный |

Находки — это вопросы ВЛАДЕЛЬЦУ, а не задачи агента: сносить ветки, закрывать
вопросы и объявлять план брошенным решает он. Задача аудита — принести список.

## Расписание

Ставит владелец на своём Mac, в Claude Code:

> `/schedule` → еженедельно, понедельник 09:00 Asia/Tashkent, промпт `/repo-audit`

Расписание живёт на машине владельца, а не в рантайме агентов: аудиту нужен
рабочий чекаут репозитория с историей и worktrees, которого на сервере нет.
