# Дизайн-волна, срез Д1 «Грамматика состояний» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development
> (recommended) or superpowers:executing-plans to implement this plan task-by-task.
> Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** состояние на экране несёт форму, слово И ВРЕМЯ — «в норме» отличимо от
«давно не смотрели», а «нет данных» от «нет данных уже неделю».

**Architecture:** новый токен `--unk` и тон полосы внимания правятся в одном
`globals.css`; ядро добавляет в строку здоровья отметку последней проверки;
панель получает единственный хелпер относительного времени и единственный дом
словарей состояний, откуда их берут все экраны.

**Tech Stack:** TypeScript strict · Next.js 16 / React 19 (`apps/cc`, vitest) ·
NestJS (`apps/core`, node:test из собранного `dist`) · CSS-переменные, без препроцессора

**Spec:** `docs/superpowers/specs/2026-09-07-design-wave-grammar-design.md`

## Global Constraints

- Русский язык кода и комментариев; комментарий объясняет ПРИЧИНУ, а не пересказывает код.
- TypeScript strict, `exactOptionalPropertyTypes: true`, `any` и `@ts-ignore` запрещены.
- **Миграций в срезе НЕТ**, схему БД не трогать.
- Каждая правка закрывается ассертом, который упадёт при её откате.
- Тесты ядра идут ИЗ СОБРАННОГО `dist`: без `pnpm --filter core build` новый тест не выполнится.
- Токен `--unk`: `#5c6360` (светлая) / `#9aa39b` (тёмная), во ВСЕХ ТРЁХ блоках палитры.
- Полоса внимания — существующий `--warn`. Лампа «работает» остаётся `--accent-tx`.
- Вес слова у «сломано»/«затык» — **600**, НЕ 700: IBM Plex Mono подключён в 400/500/600.
- Новое поле контракта `GET /apps/health`: `lastCheckedAt: string | null`, где `null`
  СТРОГО означает «проверок не было ни разу».
- Хелпер `export function ago(iso: string, now: Date): string` в `apps/cc/src/lib/format.ts`;
  `now` параметром, не `new Date()` внутри.
- Единственный дом словарей состояний — новый `apps/cc/src/lib/state.ts`.
- Тема в срезе НЕ трогается: тёмные экраны выглядят ровно как до него.

```ts
 * и `--accent-tx` — один и тот же #b8480f, так что «разные имена» ещё не

type Правило = { контекст: string; селектор: string; тело: string };

/**
 * Правила файла скобочным сканером: контекст (условие охватывающего `@media`),
 * селектор и тело. Контекст обязателен: селектор `:root:not([data-theme="light"])`
 * сам по себе не говорит, что он внутри медиавыражения, а вторая ветка тёмной
 * темы отличается от первой ровно этим.
 */
function правила(source: string): Правило[] {
  const без = source.replace(/\/\*[\s\S]*?\*\//g, "");
  const собранные: Правило[] = [];
  const стек: string[] = [];
  let буфер = "";
  for (const ch of без) {
    if (ch === "{") {
      стек.push(буфер.trim());
      буфер = "";
    } else if (ch === "}") {
      const голова = стек.pop() ?? "";
      собранные.push({ контекст: стек.join(" "), селектор: голова, тело: буфер });
      буфер = "";
    } else буфер += ch;
  }
  return собранные;
}

/** Объявления кастомных свойств в теле правила: имя → значение. */
function токены(тело: string): Map<string, string> {
  const карта = new Map<string, string>();
  for (const m of тело.matchAll(/(--[a-z0-9-]+)\s*:\s*([^;{}]+)/gi)) {
    карта.set(m[1] ?? "", (m[2] ?? "").trim());
  }
  return карта;
}

type Ветка = { имя: string; контекст: string; селектор: string };

/* Три блока палитры: светлая база и ДВЕ ветки тёмной темы. Отдельными
   константами, а не индексами массива: `ВЕТКИ[1]` в тесте ничего не называет. */

const ТЁМНАЯ_СИСТЕМНАЯ: Ветка = {
  имя: "тёмная системная (@media prefers-color-scheme: dark)",
  контекст: "@media (prefers-color-scheme: dark)",
  селектор: ':root:not([data-theme="light"])',

  контекст: "",
  селектор: ':root[data-theme="dark"]',
};
const ВЕТКИ: readonly Ветка[] = [СВЕТЛАЯ, ТЁМНАЯ_СИСТЕМНАЯ, ТЁМНАЯ_ВЫБРАННАЯ];

/** Палитра одной ветки: имя токена → значение. */
function палитра(ветка: Ветка): Map<string, string> {
  const найдено = правила(css).filter(
    (r) => r.контекст === ветка.контекст && r.селектор === ветка.селектор,
  );
  expect(найдено.length, `блок палитры «${ветка.имя}» в globals.css не найден`).toBeGreaterThan(0);
  const карта = new Map<string, string>();
  for (const r of найдено) for (const [имя, значение] of токены(r.тело)) карта.set(имя, значение);
  return карта;
}

/**
 * Имя токена, которым правило задаёт свойство. Сравнивать имя честнее, чем
 * текст правила: `border-left: 3px solid var(--warn)` и
 * `border-left: 3px var(--warn) solid` — одно и то же.
 */
function токенСвойства(селектор: string, свойство: string): string | null {
  for (const r of правила(css)) {
    if (!r.селектор.split(",").some((s) => s.trim() === селектор)) continue;
    const все = [...r.тело.matchAll(new RegExp(`(?:^|[;\\s])${свойство}\\s*:\\s*([^;{}]+)`, "gi"))];
    const значение = все.at(-1)?.[1] ?? "";
    const токен = значение.match(/var\(\s*(--[a-z0-9-]+)/i);
    if (токен) return токен[1] ?? null;
  }
  return null;
}

/** Числа контраста («5,58») из комментария на строке объявления токена. */
function контрастВКомментарии(имя: string): string[] {
  return css
    .split("\n")
    .filter((строка) => new RegExp(`^\\s*${имя}\\s*:`).test(строка))
    .flatMap((строка) => [...строка.matchAll(/\d+,\d+/g)].map((m) => m[0] ?? ""));
}
```

## Задача 2. `lastCheckedAt` в контракте `GET /apps/health` (ядро)

Строке здоровья добавляется ВТОРАЯ отметка времени — «когда источник в последний
раз проверялся», отдельно от существующей `at` («момент последнего события»).
Без неё «нет данных» неотличимо от «нет данных уже неделю» (спека §1.2,
требования Р-Д1-2 и Р-Д1-3).

**ОПРЕДЕЛЕНИЕ, ОТ КОТОРОГО ВСЁ СЧИТАЕТСЯ.** Проверка — это фактическое
обращение СОБСТВЕННОГО механизма источника: прогон монитора, закрытая доставка,
сигнал бота, завершённый вызов модели. Наше чтение базы на этот HTTP-запрос
проверкой НЕ является: журнал, прочитанный только что, ничего об источнике не
проверил. Если бы считали иначе, у всех строк стояло бы «проверено только что»,
и различие «не запускался» / «последняя проверка N назад» умерло бы в тот же
день, когда появилось.

Миграций в задаче нет, ни одного нового запроса нет: все нужные моменты служба
уже читает сегодня.

```ts
   * доставки, сигнала бота, завершённого вызова модели.

   * было» — разные утверждения, и первое молча съело бы второе на стыке с
```

```ts
/**
 * Момент последней проверки — ПОВЕРХ готового вердикта.
 *
 * У одного источника момент проверки ОДИН на все ветки правил: выключенный
 * монитор, молчащий, упавший и прошедший проверялись в один и тот же миг — в
 * свой последний прогон. Вердикт при этом у каждой ветки свой. Поэтому момент
 * считается один раз на входе и накладывается на результат, а не повторяется в
 * каждой ветке: повторённый, он потерялся бы там, где сегодня теряется `at`.
 */
function сПроверкой(строка: HealthRow, проверено: Date | null): HealthRow {
  return проверено === null ? строка : { ...строка, lastCheckedAt: проверено.toISOString() };
}

/**
 * Позднейший из известных моментов; ни одного не известно — `null`.
 *
 * ПОЗДНЕЙШИЙ, А НЕ ПЕРВЫЙ ПО СПИСКУ — в этом отличие от `ourvendAt`, который
 * отдаёт предпочтение последнему УСПЕХУ. «Когда проверяли» — это максимум: при
 * серии отказов последний успех недельной давности назвал бы проверкой прошлую
 * неделю, хотя сбор запускается каждые три часа и каждый раз падает.
 *
 * ЭКСПОРТИРУЕТСЯ, ЧТОБЫ ТАКОЙ ФУНКЦИИ БЫЛО РОВНО ОДНА: служба
 * (`apps-health.service.ts`) держала свою копию под именем `позднее` над
 * значениями СУБД, и второй «максимум двух дат» в том же срезе — начало
 * расхождения.
 */
export function позднееИз(a: Date | null | undefined, b: Date | null | undefined): Date | null {
  const x = a ?? null;
  const y = b ?? null;
  if (x === null) return y;
  if (y === null) return x;
  return y.getTime() > x.getTime() ? y : x;
}

/**
 * ЧТО СЧИТАЕТСЯ ПРОВЕРКОЙ У КАЖДОГО ИСТОЧНИКА — шесть ответов рядом.
 *
 * Вопрос один («когда этот источник в последний раз проверялся»), ответ у
 * каждого свой, и врозь эти ответы разъехались бы так же, как разъехались три
 * словаря состояний в панели. Ниже — экспортируемые входы; правила оценки
 * остались нетронутыми в приватных `вердикт*` ниже по файлу.
 */

/**
 * Строка монитора + момент последней проверки.
 *
 * ПРОВЕРКА МОНИТОРА — ЭТО ЕГО ПРОГОН. Другого мерила у Core нет: источник о
 * себе не рассказывает, известно ровно то, что записал последний тик. Прогонов
 * нет — проверок не было ни разу, и `null` здесь не заглушка, а факт.
 *
 * МОМЕНТ ЖИВЁТ И ТАМ, ГДЕ НЕТ `at`. Выключенный монитор и монитор вне снимка
 * отдают строку без `at` (`молчаливыйИсточник` такого аргумента не принимает),
 * но проверялись они в свой последний прогон.
 */
export function rowFromMonitor(face: FaceMeta, input: MonitorRowInput): HealthRow {
  return сПроверкой(вердиктМонитора(face, input), input.lastRun?.at ?? null);
}

/**
 * Сбор OurVend + момент последней проверки.
 *
 * ПОЗДНЕЙШИЙ ИЗ ДВУХ ИЗВЕСТНЫХ МОМЕНТОВ, потому что у каждого свой пробел.
 * Отчёт `/ourvend/health` знает только УСПЕХИ (`lastSuccessAt`): при серии
 * отказов сбор тикает каждые три часа и каждый раз падает — проверки идут, а
 * успеха нет неделю. Журнал прогонов (`lastRun.at`) знает и отказы, но
 * чистится ретенцией. Число прогонов (`runs`) момента не несёт вовсе, поэтому
 * судить по нему нечем.
 */
export function rowFromOurvendSync(face: FaceMeta, input: OurvendSyncInput): HealthRow {
  return сПроверкой(
    вердиктСбора(face, input),
    позднееИз(разобрать(input.health?.lastSuccessAt ?? null), input.lastRun?.at),
  );
}

/**
 * Учётный снимок OurVend + момент последней проверки.
 *
 * ТОЛЬКО ТИК МОНИТОРА, И БОЛЬШЕ ВЗЯТЬ НЕОТКУДА. В отчёте учёта нет ни одного
 * момента: `snapshotStale` — готовый вердикт, `salesLagShownH` — часы, да ещё
 * ОКРУГЛЁННЫЕ ДЛЯ ПОКАЗА. Вычесть лаг из `now` значило бы выдумать момент с
 * точностью до часа и назвать выдумку проверкой.
 */
export function rowFromOurvendAccounting(face: FaceMeta, input: OurvendAccountingInput): HealthRow {
  return сПроверкой(вердиктУчёта(face, input), input.lastRun?.at ?? null);
}

/**
 * Очередь доставок + момент последней проверки.
 *
 * ПРОВЕРКА — ПОСЛЕДНЯЯ ЗАКРЫТАЯ ДОСТАВКА, любым исходом: ушла, пропущена,
 * отказала. Каждая закрытая строка — проход диспетчера, то есть настоящая
 * попытка достучаться до Notion. Пропуск — тоже проход («ключа нет»), и рядом
 * с «источник не настроен» он говорит владельцу важное: диспетчер жив.
 *
 * `oldestPendingAt` В ПРОВЕРКУ НЕ ГОДИТСЯ, хотя дата у него есть: это момент
 * СОЗДАНИЯ строки, которую мы положили сами. Вставшая очередь выглядела бы
 * «проверенной пять минут назад» ровно потому, что в неё подкладывают новые
 * доставки, которые никто не разбирает.
 */
export function rowFromOutbox(face: FaceMeta, input: OutboxRowInput): HealthRow {
  return сПроверкой(
    вердиктДоставок(face, input),
    позднееИз(позднееИз(input.lastSentAt, input.lastSkippedAt), input.lastFailedAt),
  );
}

/**
 * Heartbeat бота + момент последней проверки.
 *
 * ЗДЕСЬ ПРОВЕРКА И СОБЫТИЕ — ОДНО И ТО ЖЕ: сигнал «я жив» и есть проверка
 * поллера, и `lastCheckedAt` совпадает с `at`. Совпадение записано намеренно —
 * иначе следующий автор пойдёт искать боту второй источник времени.
 */
export function rowFromHeartbeat(face: FaceMeta, input: HeartbeatRowInput): HealthRow {
  return сПроверкой(вердиктСигнала(face, input), input.lastAt);
}

/**
 * Ledger моделей + момент последней проверки.
 *
 * ПРОВЕРКА — ПОСЛЕДНИЙ ЗАВЕРШЁННЫЙ ВЫЗОВ, и отказавший тоже: попытка позвать
 * провайдера состоялась, а её исход строка уже цитирует. Битую дату
 * отбрасываем тем же `разобрать`, что и вердикт: она ушла бы в `toISOString()`
 * и уронила бы ВЕСЬ ответ. Монитор ledger не ответил (`monitoring === null`) —
 * о вызовах не известно ничего, и это `null`.
 */
export function rowFromLlm(face: FaceMeta, input: LlmRowInput): HealthRow {
  return сПроверкой(
    вердиктМоделей(face, input),
    разобрать(input.monitoring?.latestCompletedAt ?? null) ?? null,
  );
}
```

```ts
 * `now` — ПАРАМЕТРОМ, а не `new Date()` внутри, по двум причинам. Первая — та
 * же, что у доски рутин (`lib/crons.ts`) и сетки агентов: считать надо от
 * времени CORE (`AppsHealth.now`, `AgentsStatus.now`), иначе на границе суток
 * панель подпишет вчерашнюю проверку сегодняшним днём. Вторая — тест: функция
 * от аргументов проверяется границами, а функция от часов машины протухает, и
 * ассерт «2 дня назад» покраснел бы сам через две недели.
 */
export function ago(iso: string, now: Date): string {
  const прошло = now.getTime() - new Date(iso).getTime();
  // Мусор вместо даты — прочерк, а не «NaN дней назад»: тот же довод, что у
  // `count()` ниже — русскую фразу с числом владелец прочитает как ЧАСТЬ
  // ОТЧЁТА, а не как отказ разобрать данные.
  if (!Number.isFinite(прошло)) return "—";
  // Отрицательная разница — это отметка «из будущего», и она нормальна: часы
  // Core и момент, попавший в снимок, расходятся на секунды при любом запросе.
  // «−1 минуту назад» не фраза, а свежее «только что» здесь ближе к правде.
  const минут = Math.floor(Math.max(прошло, 0) / 60_000);
  if (минут < 1) return "только что";
  if (минут < 60) return `${минут} ${plural(минут, "минуту", "минуты", "минут")} назад`;
  const часов = Math.floor(минут / 60);
  if (часов < 24) return `${часов} ${plural(часов, "час", "часа", "часов")} назад`;
  // Сутки — САМАЯ КРУПНАЯ единица. Недель и месяцев не заводим: «45 дней
  // назад» владелец сравнивает в уме с порогом («месяц не проверялось»), а
  // «1 месяц назад» прячет разницу между 31 и 59 днями — ровно то, ради чего
  // давность и печатается. Сутки считаются ПРОШЕДШИМ временем, а не разницей
  // календарных дат: календарь дал бы «1 день назад» через две минуты после
  // полуночи.
  const дней = Math.floor(часов / 24);
  return `${дней} ${plural(дней, "день", "дня", "дней")} назад`;
}

```

```tsx
 * Что печатает колонка времени (Р-Д1-2, Р-Д1-3).
 *
 * У КАЖДОГО СОСТОЯНИЯ СВОЙ ВОПРОС О ВРЕМЕНИ, и общая формулировка на все три
 * соврала бы дважды:
 *
 * - «в порядке» отвечает «когда проверяли». Без этой отметки зелёная строка
 *   утверждает только «когда-то было хорошо».
 * - «не оценить» отвечает «давно ли молчим» — но ТОЛЬКО если проверки БЫЛИ.
 *   У источника без единого прогона давности не существует: число дней там
 *   было бы выдумкой, а не оценкой, поэтому `null` печатает слово, а не цифру.
 * - «сломано» отвечает «когда сломалось». Это момент СОБЫТИЯ (`at`), и
 *   подменять его временем проверки нельзя.
 */
function времяСостояния(row: AppsHealthRow, now: Date): string {
  switch (row.state) {
    case "ok":
      // `null` у зелёной строки — дефект провода (Core обязан знать момент
      // проверки у того, что проверил). Говорим об этом словами: прочерк
      // выглядел бы как «времени тут не бывает» и спрятал бы поломку контракта.
      return row.lastCheckedAt !== null
        ? `проверено ${when(row.lastCheckedAt)}`
        : "проверка не датирована";
    case "unknown":
      return row.lastCheckedAt === null
        ? "не запускался"
        : `последняя проверка ${ago(row.lastCheckedAt, now)} назад`;
    case "bad":
      // Прочерк, а не пустота: колонка не должна молча съезжать. Ярлыка
      // («проверено», «сломалось») здесь нет намеренно — `at` у разных строк
      // значит разные события (например самую старую непрошедшую доставку), и
      // единый ярлык сочинил бы смысл, которого в поле нет.
      return row.at !== undefined ? when(row.at) : "—";
  }
}

/** Строка источника: состояние словом и весом, заголовок, причина, время, ссылка на починку. */

      <div className="ab">
        <div className="an">{row.title}</div>
        <div className="as">{row.summary}</div>
        {/* Цитата источника — текстом: итог прогона и ошибка доставки приходят
            из базы, и разметкой их рендерить нельзя. */}
        {row.detail !== undefined && <div className="hint">{row.detail}</div>}
      </div>
      <div className="aw">{времяСостояния(row, now)}</div>
    </>
  );
  return row.href !== undefined ? (
    <Link href={row.href} className="approw" data-state={row.state}>
      {тело}
    </Link>
  ) : (
    <div className="approw" data-state={row.state}>
      {тело}
    </div>
  );
}
```

```tsx
type ПравилоCss = { media: string | null; selector: string; body: string };

/** Объявляющие правила файла, каждое — со СВОИМ медиазапросом, а не склеенное с ним. */
function правилаCss(source: string): ПравилоCss[] {
  const без = source.replace(/\/\*[\s\S]*?\*\//g, "");
  const собранные: ПравилоCss[] = [];
  const стек: string[] = [];
  let буфер = "";
  for (const ch of без) {
    if (ch === "{") {
      стек.push(буфер.trim());
      буфер = "";
    } else if (ch === "}") {
      const заголовок = стек.pop() ?? "";
      // У самого `@media` объявлений нет: его тело — вложенные правила, они уже
      // разобраны своими скобками.
      if (!заголовок.startsWith("@")) {
        собранные.push({
          media: стек.find((s) => s.startsWith("@media")) ?? null,
          selector: заголовок,
          body: буфер,
        });
      }
      буфер = "";
    } else буфер += ch;
  }
  return собранные;
}

/** Верхнеуровневые дорожки значения: пробел внутри `minmax(0, 1fr)` не делит. */
function дорожки(значение: string): string[] {
  const части: string[] = [];
  let глубина = 0;
  let буфер = "";
  for (const ch of значение) {
    if (ch === "(") глубина += 1;
    if (ch === ")") глубина -= 1;
    if (глубина === 0 && /\s/.test(ch)) {
      if (буфер !== "") части.push(буфер);
      буфер = "";
      continue;
    }
    буфер += ch;
  }
  if (буфер !== "") части.push(буфер);
  return части;
}

/**
 * Сколько колонок задаёт значение: `1fr`, `minmax(0, 1fr)`, `1fr 1fr 1fr` и
 * `repeat(3, minmax(0, 1fr))` — это 1, 1, 3 и 3. `null` — число не задано явно
 * (`repeat(auto-fill, …)`), и ступенью такое правило считать нечем.
 */
function числоКолонок(значение: string): number | null {
  let счёт = 0;
  for (const часть of дорожки(значение.trim())) {
    const повтор = /^repeat\(\s*([^,]+?)\s*,([\s\S]*)\)$/i.exec(часть);
    if (повтор === null) {
      счёт += 1;
      continue;
    }
    const раз = Number.parseInt(повтор[1] ?? "", 10);
    if (!Number.isInteger(раз)) return null;
    счёт += раз * Math.max(1, дорожки((повтор[2] ?? "").trim()).length);
  }
  return счёт;
}

function ширинаЗапроса(media: string | null, свойство: "min-width" | "max-width"): number | null {
  if (media === null) return null;
  const m = new RegExp(`\\(\\s*${свойство}\\s*:\\s*(\\d+)px\\s*\\)`).exec(media);
  return m === null ? null : Number.parseInt(m[1] ?? "", 10);
}

type Ступень = { media: string | null; от: number | null; до: number | null; колонок: number | null };

const ступениСетки: Ступень[] = правилаCss(стилиПанели).flatMap((rule) => {
  if (!rule.selector.includes(".aggrid")) return [];
  const последнее = [...rule.body.matchAll(/grid-template-columns\s*:\s*([^;{}]+)/gi)].at(-1);
  if (последнее === undefined) return [];
  return [
    {
      media: rule.media,
      от: ширинаЗапроса(rule.media, "min-width"),
      до: ширинаЗапроса(rule.media, "max-width"),
      колонок: числоКолонок(последнее[1] ?? ""),
    },
  ];
});

/** Правила, задающие НАЧЕРТАНИЕ лампы состояния (`font-weight` там, где есть `.led`). */
function весаЛамп(source: string): { selector: string; weight: number }[] {
  const итог: { selector: string; weight: number }[] = [];
  for (const rule of правилаCss(source)) {
    if (!rule.selector.includes(".led")) continue;
    for (const m of rule.body.matchAll(/(?:^|[;\s])font-weight\s*:\s*([^;{}]+?)\s*(?=;|$)/gi)) {
      const вес = Number.parseInt((m[1] ?? "").replace(/!\s*important$/i, "").trim(), 10);
      if (!Number.isInteger(вес)) continue;
      for (const sel of rule.selector.split(",")) итог.push({ selector: sel.trim(), weight: вес });
    }
  }
  return итог;
}
```

````
### 4.1. Анатомия состояния: форма + слово + время

Состояние обязано нести три вещи. Цвет — четвёртая и необязательная: он теряется при дальтонизме, на
плохом экране и в печати. **Время — такая же часть состояния, как слово:** без давности «в норме»
неотличимо от «давно не смотрели», а «нет данных» — от «нет данных уже неделю».

| Смысл | Форма (`.led`) | Слово (пример) | Время | Вес слова |
|---|---|---|---|---|
| в норме | залитый квадрат 8×8, `--ok` (`.led.idle`) | «в порядке» | отметка последней ПРОВЕРКИ (`lastCheckedAt`) — обязательна | 400 |
| работает | залитый квадрат, `--accent-tx` (`.led.working`) | «работает» | момент, с которого длится (`since`) | 400 |
| сломано | залитый квадрат, `--err` (`.led.blocked`) | «сломано» / «затык» | момент, с которого длится (`since`) | **600** |
| нет данных | ПУСТОЙ квадрат со штриховкой, `--unk` (`.led.unknown`) | «не оценить» | «не запускался» — если прогонов не было ни разу; «последняя проверка N назад» — если были | 400 |

- **Словарь состояний ОДИН** — `apps/cc/src/lib/state.ts`. Слово и класс лампы берутся оттуда, второго
  словаря в панели не заводить: он расходится с первым на первой же правке, и один агент «работал» бы на
  главной и «молчал» в собственной карточке.
- **Слово выбирает экран под свой вопрос, смысл лампы — нет.** `/apps` спрашивает «здоров ли источник»
  («в порядке / сломано / не оценить»), сетка агентов — «занят ли агент» («работает / затык / молчит / на
  паузе»). Поэтому в сетке агентов ЗЕЛЁНОЙ ЛАМПЫ НЕТ НИ У ОДНОГО СОСТОЯНИЯ: `--ok` — утверждение о
  здоровье, а выключенный агент здоровым не является. «Молчит» и «на паузе» — базовая `.led` (`--tx-2`):
  состояние известно, поэтому квадрат залит, но нормой оно не является.
- **Лампа «работает» — `--accent-tx`, а не `--accent`:** §1 отдаёт `--accent` сплошным заливкам с тёмными
  чернилами, а лампа — мелкая нетекстовая метка, и заливка ею нарушила бы «оранжевого мало».
- **«Нет данных» отличается ФОРМОЙ, а не оттенком серого:** заливка значит «ответ есть», пустой контур —
  «ответа нет». Так «мы не знаем» не путается с «пропущено: повода нет» (`.run-led.muted` — тоже залитый
  серый) даже на монохромном экране. Зелёного у него нет ни в одной теме: ноль прогонов не имеет права
  выглядеть как успешный прогон.
- **«Не запускался» — не число.** У того, чего не происходило, давности не существует: печатать «12 дней
  назад» у источника без единого прогона значит выдумывать. Отметка ПРОВЕРКИ (`lastCheckedAt`) — своё
  поле, отдельное от момента последнего события (`at`): проверка могла быть без события.

### 4.2. Левые полосы внимания

Полоса значит «эту строку видно, не читая слов».

- **Ширина — всегда 3px** (`border-left: 3px solid …`): так у `.trow.hot`, `.qcard`,
  `.approw[data-state="bad"]`, `.agtile`, `.maprow.hot`, `.prow.hot`, `.urow`, `.jrow`, `.sect.appr`.
  `2px` — не полоса внимания, а группировка (`.jgrp`: происхождение записи).
- **Тон — по смыслу, а не «поярче»:** `--err` — сломано / затык (работа не идёт и сама не пойдёт);
  `--warn` — молчит из-за поломки, то есть не авария, но и не спокойствие; `--hot` — тревога
  бизнес-экрана (`.trow.hot`, `.qcard`); `--ok` — подтверждено; `--line` — нейтральная строка без сигнала.
- **Полоса внимания и лампа «работает» НЕ носят один тон.** Оба смысла жили на `--accent-tx` и на одной
  плитке встречались рядом. Лампа остаётся оранжевой (§1), полоса внимания — `--warn`: светлая 5,93 / 5,37,
  тёмная 9,03 / 9,94 при пороге нетекстового элемента 3,0 (прежний `--accent-tx` давал 5,29 / 8,22 — новый
  тон и смыслы разводит, и контрастнее).
- **Одна полоса на элемент.** `border-left` — одно свойство: `.agtile[data-state="blocked"]` и
  `.agtile[data-attention="true"]` не складываются, побеждает последнее правило в каскаде. Сегодня они
````
